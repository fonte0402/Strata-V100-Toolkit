# Strata V100 Toolkit

[English](README.md) · [测试数据](docs/BENCHMARKS.md) · [上游 Strata](https://github.com/Niko1221/Strata)

**单张 Tesla V100 32GB 跑 Qwen3.8-Flash-Next：最新严格JSON短筛实测最高89.6 token/s。**

本项目记录单卡V100的真实测试，并整理可移植服务工具。最新本机测试来自 **Linux / Strata v0.1.41**；较早 **i9-13900F + DDR4 + PCIe Gen3 x4 + Windows** 测试及已发布工具作为历史材料保留。推理引擎来自 Strata。

## 实测表现

### Linux 最新实测 · 2026-10-23：老 V100 依然能打

**单卡 32GB V100，严格 JSON 实测 89.6 token/s，8,216-token 文档任务实测 87.7 token/s。** 这次晒的是本机真实测量，不是别人的显卡跑分。

当前本机路线是 **Ubuntu 26.04.1 + Xeon E5-1650 v4（6核12线程）+ 1× Tesla V100-PCIE-32GB**，引擎 **Strata v0.1.41**，模型 **Qwen3.8-Flash-Next GSQ-RCO IQ3_XXS**。下方较早的 Windows/i9 数据来自另一台主机和另一套协议，不能相减当作迁移收益。

固定的 **10月15日调优、ESP关闭** 基准，每题3轮中位数，12份参考答案均通过严格任务检查：

| 固定参考任务 | 引擎 decode 中位速度 |
|---|---:|
| 中文故事 | **61.58 token/s** |
| 代码 | **71.66 token/s** |
| 严格 JSON | **87.23 token/s** |
| 8K 文档 | **84.47 token/s** |

最近的完整原题顺序短筛保留“预热→故事→代码→JSON→8K”，只切换 SM70 查表：

| 任务 | SM70=0 | SM70=1 | 严格质量 |
|---|---:|---:|---|
| 代码 | 69.6 | **70.4 token/s** | 两臂通过 |
| JSON · 输出402 tokens | 86.5 | **89.6 token/s** | 两臂通过、正文相同 |
| 8K文档 · 输出170 tokens | 83.8 | **87.7 token/s** | 两臂通过、正文相同 |

本短筛每题每臂只有1次观测。候选故事严格语义未通过，不计入速度亮点；代码仍低于固定参考。**不宣称原四题整体提速，也不把单次观测写成新的生产中位数。** 8K题实际输入8,216 tokens；配置256K上下文不等于测了256K长输入。

**SM70 的小而实在的收益：** 后续补了一对反序测试（先开后关），每臂仅“预热+JSON+8K”，总计6次调用（含预热）：

| 任务 | 关闭→开启 decode | 完整请求等待，关闭→开启 |
|---|---:|---:|
| JSON · 相同402-token答案 | 78.7 → **81.3 token/s（+3.30%）** | 6.299 → **6.167秒** |
| 8K · 相同170-token答案 | 83.0 → **86.3 token/s（+3.98%）** | 8.070 → **8.020秒** |

4份测量答案严格检查全部通过，每对全文SHA和token数相同。短序列改变了专家驻留前序，是独立工作负载；TTFT分别增加约31/29毫秒，不能把decode增幅当成完整等待增幅。已有SM70组件逐位检查、64组真实激活回放通过；同宽受控teacher-forced对照的已记录评分和局部原始top2也一致。覆盖范围有限，SM70目前仍是可选候选，未转生产默认。

**CPU也有逐位一致的成果：** 隔离研究中的精确IQ3_S索引优化，31个真实CPU批次输出全部逐位相同；27个受影响批次的耗时中位数，热权重减少 **11.12%**、冷权重减少 **9.13%**。这是局部CPU微基准，不是整机生成提速；热测尾部反例保留，定制原生库未部署。

Linux共用条件：配置256K上下文、Vision开启、**native ESP关闭（`cvec=0`）**、会话缓存关闭、**实际15,329专家槽**、MTP上限3、6 workers、INT8 KV/resident32768、adaptive 1/160/0.97、CPU_SHARE=0、PCIe比例0.55。[测试口径与边界](docs/BENCHMARKS.md#linux-update--2026-10-23)。

本次只公开说明文档；不上传Linux启动器修改、候选内核、模型资产或私人运行日志。生产仍保留原ESP开启配方，上面的ESP关闭研究档与生产默认分开记录。

## 已发布Windows工具能力

- **Text / Vision 配置**：8K、32K、64K、128K、256K；上下文与视觉能力在启动时固定。
- **请求级 Thinking 与 ESP**：思考强度由客户端选择；ESP 可在启动配置中加载、通过网页或单次 API 请求切换。显式请求参数优先于共享默认设置。
- **网页运维**：Chat、Sampling 共享默认设置、Monitor，以及 **Shutdown**。
- **持久 token 用量**：本次运行、今日、累计；跨重启保存，初始输入与内部续写缓存分别记录。
- **可移植服务管理**：支持迁移目录、外置资产和认证文件；启停核对进程创建时间、指纹与端口归属。

ESP 为实验功能；本项目公开实测，不把它视为零质量影响的保证。
